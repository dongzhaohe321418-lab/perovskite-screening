# WP3-V6: does replay protect the Sr-vacancy repulsion at the learning rate and EMA of V3? (pre-specification)

Written 2026-11-24T00:44Z, after V1 to V5 were read (`WP3_RETESTS.md`, `WP3_RETESTS_V4V5.md`) and before any V6 step other than
the transfer of its input files. Post hoc with respect to WP3 and V1 to V5; a diagnostic, not an adoption test. No
model is adopted on this evidence.

**Why.** V2 (multi-head replay) kept the repulsion but stayed above the 45 meV/A force line; it changed three things
at once against WP3 (learning rate 1e-4, EMA decay 0.99999, replay), and its EMA time constant is about the length of
the run. V3 and V5 (single head, learning rate 1e-4, EMA 0.99) reach WP3-level forces and lose about half of the
repulsion. No arm has replay with the optimiser settings of V3. V6 is that arm.

**Arm.** The V2 command with three changes: `--force_mh_ft_lr True` (so that mace-torch does not overwrite the
optimiser settings in multi-head mode), `--lr 0.0001` and `--ema_decay 0.99` (as V3; 0.99 is also what the V2
command line carried before mace-torch overwrote it). Seed 123, 100 epochs, name wp3v6. Everything else as V2: the
same 201 training frames, validation set, E0s, weights (w_E 70 000, w_F 100), batch 2, float64, `--keep_checkpoints`.

**Two differences of execution from V2, with a gate.**
- V6 runs on the project's compute node (x86, 64 cores; mace-torch 0.3.16, torch 2.14.1, e3nn 0.4.4, the versions of
  V1 to V5), not on the laptop that ran V1 to V5.
- The node cannot download the Materials Project replay file. V6 is therefore given the replay subset that V2
  selected (`mp_finetuning-wp3v2_run-123.xyz`, 2000 configurations, sha256
  `9b809d17337fcc75c4922da9546e934402a7dabf60d5ada2f73a5064495a0776`) as `--pt_train_file`, in place of `mp`. By
  reading the mace-torch 0.3.16 source, `mp` selects the subset and then loads it with the same call that loads a
  file given by path.
- **Gate G-replay, read before any V6 read-out.** The V6 log must show "Total number of configurations in
  pretraining: train=1800, valid=200", the pt_head key specification of the V2 log, and Initial validation losses
  equal to V2's for both heads (pt_head 5.77738917; Default 0.03053121) to a relative 1e-5 (the two machines differ
  in floating-point arithmetic). If the gate fails, V6 is stopped and is not a result.
- The foundation model file on the node has the sha256 of the model of V1 to V5
  (`01bfe22100139f424713cf921144e5509cbe353d67aa9fa1be9c6e1e0ed35845`); checked before this note was written.

**Read-outs** (fixed now; as V3). On the selected model, with the relocatable evaluator `eval_retests.py`, head
"Default": P1 (m30 Sr far-referenced E_b error RMS) and P3 (force RMSE on the 46 m30/m32 test frames). The evaluator
has not been run on any model yet. **Gate G-eval2:** on the node it must first reproduce, for the foundation model,
P1 = 9.20 meV and P3 = 86.81 meV/A to the printed digits; if it does not, V6 is evaluated on the laptop with
`eval_v1.py` instead. The m21 values and the Sr hinge and flank E_b at the kept checkpoints are reported, not read by
a rule.

**Readings** (fixed now). P1_low = 50.94 meV is the mean of V3 (47.04) and V5 (54.84); the limit is 20 meV, as in
V4V5_PRESPEC (the seed effect measured there is 7.80 meV).
- Class by V3's rule: "kept" (P1 <= 25 meV and P3 <= 45 meV/A), "lost" (P1 > 50 with P3 <= 45), "under-trained"
  (P3 > 45), otherwise "partial".
- "replay protects at this rate": P1(V6) <= P1_low - 20 = 30.94 meV and P3 <= 45.
- "no resolved effect of replay at this rate": |P1(V6) - P1_low| <= 20 meV and P3 <= 45.
- "replay worse at this rate": P1(V6) - P1_low > 20 meV and P3 <= 45; reported as unexplained.
- "under-trained": P3 > 45 meV/A. Then replay with these settings does not reach WP3-level forces in 100 epochs; no
  further arm follows from this note.
- A "protects" outcome is one seed on one data set against two seeds without replay, on a different machine; the
  machine is confounded with the arm. It would not show that replay is a cure.

**Stopping rule for cost.** If the first two epochs project more than 30 h for 100 epochs on the node, the run is
stopped; that is not a result.

**Limits.** The used test set; P1 on 3 sites of one host; one seed; another machine than V1 to V5.

## Execution note 1 (written 2026-11-24, after the launch and the reading of gate G-replay; before any V6 read-out)

**A first launch failed before training.** Started 2026-11-24T00:46:36Z; mace-torch stopped while loading the replay
file with `ValueError: None of 'REF_energy', 'REF_forces', and 'dipole' found`. No epoch ran and no model was written.
Its files are kept on the node, apart from the run directory.

**Cause, and a correction to the pre-specification.** The statement above that `mp` "loads [the subset] with the same
call that loads a file given by path" is wrong in one respect. With `--pt_train_file mp`, mace-torch 0.3.16 reads the
replay file with the keys `energy`, `forces`, `stress`; with a path it reads it with the keys of the fine-tuning
head, here `REF_energy`, `REF_forces`, `REF_stress`. The subset file carries the former names.

**Deviation.** V6 is given a copy of the subset in which the three key names are changed and nothing else: in each
of the 2000 comment lines `energy=` becomes `REF_energy=`, `stress=` becomes `REF_stress=`, and in the Properties
field `forces:R:3` becomes `REF_forces:R:3`. Checked on the copy: 2000 lines carry each new name, no line carries the
old ` energy=` key, and the line count is unchanged (59 229). sha256 of the copy
`ca3b577caf4e000d1d4d5e06e19b10bc37bdf384b1eb3541ffa8c6a3fdabe1af`. No number in the file was edited; that the values
are read as before is checked by the gate below, not by inspection.

**Second launch.** Started 2026-11-24T00:49:10Z with the same command, `--pt_train_file` pointing at the copy.

**Gate G-replay, as read from the V6 log.**
- "Total number of configurations in pretraining: train=1800, valid=200": met.
- Initial validation loss, pt_head: 5.77738917 (V2: 5.77738917), with RMSE_E 81.39 meV/atom, RMSE_F 113.12 meV/A,
  RMSE_stress 3.79 meV/A^3, the printed values of the V2 log. Default: 0.03053121 (V2: 0.03053121). Met to the
